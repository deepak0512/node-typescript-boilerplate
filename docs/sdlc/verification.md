## 5. Limitations and Environment Notes

1. **Windows-only skips.** Two integration tests skip on Windows:
   - the file-mode test, because there are no POSIX mode bits;
   - the symlink-escape test, because creating symlinks needs elevated rights.

   Both run on the Linux CI runner. This local run was on Windows, so **those two have not yet been observed passing**. The CI run on the PR is their evidence.
2. **Known deviations accepted in the code review:**
   - CR-6: usage errors print the error message and a `--help` hint, not the full usage text.
   - CR-7: a symlink escape or non-file target exits 3, where NFR-1.4 says 2.
   - CR-8: fences nested in lists, and multi-line HTML comments, are not recognized.
   - CR-9: invisible `\p{Cf}` characters are not stripped.
3. **Live data drifts.** The cross-check reflects GitHub's data at the time of the run. Later upstream edits make `--check` exit 1 until the document is re-synced; that is intended behavior.
4. **Simplified cross-check.** The cross-check script compares against unescaped API strings. That is valid for the current upstream data, which contains no Markdown-special characters. The escaping itself is covered by the unit tests.
5. **Local tooling quirks (not product defects):**
   - With `core.autocrlf=true`, `npm run prettier:check` fails locally on CRLF checkouts; the LF clone in §1.1 passes.
   - Vitest reports "0 tests" for every file when the shell's working directory uses a lowercase drive letter (`c:\`). Rerunning from `C:\` fixes it.
